---
title: AprilTag Support
description: Use known AprilTags to anchor Mighty poses, correct drift, and align multiple cameras in a shared coordinate frame.
---

Mighty can use AprilTags as fixed landmarks for visual-inertial odometry (VIO).
Give each tag a physical size and full pose: its center position and mounting
rotation. You can enter poses manually or import a WPILib field layout. When
the camera obtains a usable pose from a matching tag, it corrects its reported
position and orientation to match your chosen coordinates.
VIO continues tracking between sightings.

Once configured, AprilTag support stays active while VIO is running. You can
close the Visualizer and the camera will continue using your saved tags.

## What you can use it for

- **A repeatable origin:** put a tag at a fixed reference point, such as a
  workbench or docking station. Looking at it aligns each new VIO session to
  the same coordinates.
- **Drift correction at checkpoints:** place known tags along a route so the
  camera can realign its output when it revisits those locations.
- **Shared coordinates across cameras:** configure the same tag map on multiple
  Mighty cameras, then let each camera observe a configured tag. Their reported
  trajectories can be displayed in the same world frame.
- **Repeatable experiments and demos:** use a fixed tag to compare trajectories
  across runs instead of relying on where each camera happened to initialize.

## Prepare a tag

Use a **tag36h11** AprilTag with a one-cell black border. Mount it flat and keep
it stationary.

You can get a tag from either of these resources:

- [Studica's online AprilTag generator](https://learn.studica.com/docs/tools/apriltag-generator/):
  select **tag36h11**, choose a tag ID and size, then download an SVG or PNG or
  print a sheet. Use the same ID in the Visualizer.
- [Official AprilRobotics tag36h11 images on GitHub](https://github.com/AprilRobotics/apriltag-imgs/tree/master/tag36h11):
  download a ready-made tag. For example, `tag36_11_00007.png` is tag ID **7**.

Print at **100% scale**, with **Fit to page** turned off, and measure the finished
print before entering its size in the Visualizer.

Measure one side of the tag's outer black square, excluding the surrounding
white margin. Enter that measurement in **centimeters**. For example, a black
square measuring 16.2 cm across needs a size of `16.2`, regardless of the paper
size. Keep the white margin visible around the tag.

The camera needs a valid saved camera/IMU calibration. Follow
[Calibration](/docs/calibration) if you have not calibrated it, or if the lens or
mount has changed.

## Map your own tags with a phone

Open the [**Phone Tag Mapper**](/tagsmapper) on your phone to build a map of tags
in a room, workshop, or warehouse. The guided tool tracks your phone, detects
**tag36h11** tags, and exports their center positions and full rotations as a
WPILib-style JSON layout. **You do not need a connected Mighty camera to map tags.**

Open the page over **HTTPS** in **[XRViewer](https://apps.apple.com/us/app/webxr-viewer/id1295998056) on iPhone or iPad**, or **Chrome on an
ARCore-compatible Android phone**. In XRViewer, allow **Camera access** for
computer vision as well as AR tracking. If tracking starts but the preview stays
blank, enable Camera access for this site in XRViewer and restart the scan.
iPhone Safari cannot run this mapper. Camera frames are processed
locally in a worker; they are not uploaded. **Explore an example map** lets you
try the interface without camera access; example exports are labeled as examples.

1. Mount flat tags with **unique IDs** and visible white margins. Use one common
   physical size, then enter the measured **outer black square** size in centimeters.
   Correct size is needed to estimate distance and pose.
2. Tap **Enable camera & tracking** and allow the requested permissions. Let
   tracking settle while looking at a well-lit, textured surface.
3. Hold the **rear camera at your chosen origin**, keep the phone upright, and
   aim it along your desired **+X** direction. Tap **Start mapping**. The camera
   position becomes `(0, 0, 0)`, including its height; **Y points left** and
   **Z points up**. To make the floor Z=0, start with the camera at floor level.
4. Walk slowly around the tags. Detected outlines and IDs appear in the camera
   preview; the 3D map shows the phone path and averaged tag poses. See each tag
   from several positions and angles, keep its whole border visible, and revisit
   earlier tags. Move sideways around a tag rather than only moving closer or
   rotating the phone. Tags needing more viewpoints are marked in the list.
   Drag the 3D view, pinch to zoom, or use **Frame map / Top view**.
5. Tap **Tags** to review XYZ in meters and roll, pitch, and yaw in degrees.
   **Delete** clears a tag's observations. A new camera sighting adds it again.
   Small tags, blur, glare, or lost tracking need a closer, steadier view.
6. Tap **Finish** to refine each tag pose against its recorded image corners,
   then review the map and **Download WPILib JSON**. Tags with unresolved poses or
   too little viewpoint diversity are excluded from the download. If none are
   ready, start another scan and capture more viewpoints. The last completed map is
   saved in this browser for review, including edits made after finishing.
7. In the [Visualizer](/viz), stop VIO and open **Device Settings → Edit Tags**.
   **Import WPILib JSON**, review the poses and size, then **Save** and restart VIO.

The mapper uses one gravity-aligned frame for the whole scan. Finish optimizes
**tag poses with the WebXR camera poses held fixed**; it does not jointly optimize
the camera trajectory or remove accumulated AR drift. Observation spread and
pixel reprojection error describe consistency, not guaranteed world accuracy.
Keep scans compact and verify known distances and mounting angles before using
the map as a reference. Surveyed poses remain preferable when precise absolute
positioning is required.

Exports preserve the origin you chose, including negative coordinates. The
`field.length` and `field.width` values estimate the map's extent; they are not
surveyed room dimensions. An optional `mighty` metadata object carries
`tagFamily: "tag36h11"` and `tagSizeM`. WPILib ignores this extension; Mighty's
Visualizer and **Python, JavaScript, and C++ SDKs** use it to preserve your
measured size. Standard WPILib files still default to **16.51 cm**, and an explicit
SDK size argument overrides the metadata.

## Configure tags in the Visualizer

1. Connect the camera and open the [Visualizer](/viz). Wait for it to connect.
2. If VIO is running, click **Stop VIO**.
3. Open **Device Settings** and find **Relocalization**.
4. Click **Relocalize using AprilTags**, or **Edit Tags** to change existing rows.
5. Fill in the tag's ID, size, orientation, and position using the table below.
   Use **Add Row** for additional tags and **-** to remove a row.
6. Click **Save**. The button in Device Settings will show **AprilTags On**.
7. Click **Start VIO**, allow tracking to initialize, and point the camera at a
   configured tag.

*The Visualizer's configuration modal, rendered with example values.*

| Field | What to enter |
| --- | --- |
| **Tag ID** | The printed tag's numeric ID, such as `7`, or `*` to match any ID. An explicit ID takes precedence over a wildcard. |
| **Size cm** | Side length of the outer black square in centimeters. The default is `16.2`; replace it with your measurement. |
| **Orientation** | **Upright** or **Facing up** shortcuts, or **Custom Pose3d** for any mounting rotation. |
| **Roll, Pitch, Yaw** | For Custom Pose3d, enter angles in **degrees**. Zero rotation is an upright tag facing +X with its top toward +Z. |
| **X, Y, Z** | Position of the **tag center** in your world frame, in **meters**. These are not the camera's position or the distance from the camera to the tag. |

For a first test, use one upright tag with its actual ID and size, and set
`X = 0`, `Y = 0`, `Z = 0`. This makes the tag center the origin. The camera's
reported position will be offset from that origin according to where it is
relative to the tag.

### Full Pose3d and orientation shortcuts

**Upright** faces **+X** with the top of the printed tag toward **+Z**.
**Facing up** faces **+Z** and preserves the existing shortcut's mounting
rotation. Choose **Custom Pose3d** for tilted tags, tags facing another wall,
or tags rotated in their own plane.

For custom poses, XYZ is the tag center in meters. Roll, pitch, and yaw use the
WPILib `Rotation3d` convention: `Rz(yaw) × Ry(pitch) × Rx(roll)`, with angles
entered in degrees. The tag's local axes are **+X out of the printed face**,
**+Y left**, and **+Z toward the top**. For example, roll `0`, pitch `0`, yaw
`90` describes an upright tag facing +Y.

Measure all tags in one common frame and use unique IDs for different
landmarks. Choose **Z pointing up**, in agreement with gravity. Use the same
origin and axes for every tag, including tags imported from another layout.
The `*` wildcard assigns the same size and pose to every otherwise
unmatched tag; it does not discover a map automatically.

### Import a WPILib field layout for FRC

Mighty uses **tag36h11**, the family used on FRC fields since 2024. Standard FRC
tags measure **6.5 inches (16.51 cm)** across the black square. See
[WPILib's AprilTag introduction](https://docs.wpilib.org/en/stable/docs/software/vision-processing/apriltag/apriltag-intro.html).

1. Download your field's WPILib AprilTag layout JSON. For a concrete example,
   use the official [2026 REBUILT welded-field layout](https://github.com/wpilibsuite/allwpilib/blob/v2026.2.2/apriltag/src/main/native/resources/edu/wpi/first/apriltag/2026-rebuilt-welded.json).
   Choose the layout that matches your actual field and season.
2. Stop VIO and open the AprilTag configuration modal.
3. Click **Import WPILib JSON** and select the file. It replaces the draft rows
   with the file's tag IDs, positions, and full rotations.
4. Review the imported rows. The importer uses **16.51 cm** for tag size because
   standard WPILib layout files do not include a size. Phone Mapper exports
   prefill the measured size instead. Change it for other nonstandard tags.
5. Click **Save**, then restart VIO. Importing alone does not change the device.

The importer preserves the JSON's field origin and axes. It does not change
origins for alliance color. See WPILib's
[AprilTagFieldLayout coordinate convention](https://github.wpilib.org/allwpilib/docs/release/java/edu/wpi/first/apriltag/AprilTagFieldLayout.html).
To return a robot-center pose, your application must also account for the
Mighty camera/IMU's mounting transform relative to the robot.

Use firmware with full tag-pose support. Older firmware rejects these imports;
it cannot apply arbitrary tag rotations. Existing Upright and Facing up
configurations continue to work.

### Saving, editing, and disabling

**Save** stores the settings on the connected camera. They survive a reboot,
and each camera has its own settings.

**Stop and restart VIO to apply changes.** The **AprilTags On** label confirms
that your settings are saved. Look for the relocalization notification to confirm
that the camera has used a tag.

To disable, stop VIO, then click **Disable** in the modal or click **AprilTags On**
in Device Settings. Both clear the saved tag configuration. Start VIO again to
track without tag relocalization. Copy down your rows first if you want to reuse
them; disabling is not a pause that preserves the rows. **Close** dismisses the
modal without saving draft edits.

## Check frequency

Mighty automatically checks for configured tags about **every 2 seconds** while
VIO is running and continues tracking between checks. You do not need to trigger
each check. The check frequency cannot be changed in the Visualizer.

## Check that it is working

Keep a configured tag fully visible and hold the camera steadily for a few
seconds; a brief glimpse may be missed. Initial alignment and large corrections
can require consistent sightings across several checks. Keep the tag in view
until the relocalization notification appears; seeing its outline once is not
enough. VIO continues tracking while a tag pose is being checked or ignored.
The Visualizer can show detected tag outlines, and a successful alignment
produces a notification such as **Tag #7 detected, relocalizing**.

The displayed position and orientation may jump as a tag corrects accumulated
drift. Tracking continues afterward, and drift can build up again between tag
sightings.

If you see no alignment, check that VIO has initialized, the calibration is
installed, the tag is from the correct family, and its ID matches a saved row.
If the position or orientation is wrong, check the measured size, centimeter
versus meter units, tag-center coordinates, and mounting rotation. Move closer
or improve lighting if the corners are small, blurred, obscured, or affected by
glare. A detection overlay alone does not confirm a successful pose alignment.
If a tag is nearly square-on to the camera, move sideways to give it a clearer
angle and hold the view steadily. An uncertain pose may be ignored until a
clearer view is available.

If multiple configured tags are visible, check that their saved poses agree in
the same coordinate frame. Conflicting tag positions or mounting rotations can
prevent an alignment. Verify each tag's measured position and mounting rotation
before trying again.

## Use multiple cameras in one frame

First follow [Multi-Camera Setup](/docs/multi-camera) to give each camera a
different USB IP range. Save the same tag map on each camera, then start VIO on
each and let it see a configured tag. Each camera aligns independently to that
shared frame. This does not synchronize the camera shutters or perform stereo
calibration.

The [multi-camera AprilTag Python example](https://github.com/asadm/mighty-protocol/tree/main/examples/python/multi_camera_apriltag)
shows two camera previews with tag overlays, both VIO trajectories in one 3D
view, and relocalization notifications. It also supports recording and replaying
ROS1 bags. Follow the example's setup instructions to try it with two cameras.

## Configure from an application

Python, JavaScript, and C++ provide a WPILib importer with no WPILib runtime
dependency. Each validates the entire layout, normalizes rotations, and uploads
one complete `apriltags` configuration. Mapper exports supply the measured tag
size automatically; omit the optional size argument to use that metadata.
Invalid layouts are rejected before
sending a configuration. The call replaces the saved tag map.

Stop VIO before importing, check the result, and restart VIO after a successful
save. The helpers do not stop or restart tracking automatically.

```python
from pathlib import Path
from mighty_sdk import parse_wpilib_field_layout

layout_json = Path("2026-rebuilt-welded.json").read_text()
tag_map = parse_wpilib_field_layout(layout_json)  # inspect before upload
# tag_map["tags"][0]: tag_id, size_m, position_m, orientation_xyzw
# orientation_xyzw here uses WPILib's tag axes.
result = client.import_wpilib_field_layout(layout_json, tag_size_m=0.1651)
if not result["ok"]:
    raise RuntimeError(result["message"])
```

```js
import { parseWpilibFieldLayout } from "mighty-protocol";

const layoutJson = await file.text(); // browser File selected by your user
const tagMap = parseWpilibFieldLayout(layoutJson); // inspect before upload
// tagMap.tags[0]: tagId, sizeM, positionM, orientationXyzw
const result = await client.importWpilibFieldLayout(layoutJson, { tagSizeM: 0.1651 });
if (!result.ok) throw new Error(result.message);
```

```cpp
#include <fstream>
#include <iterator>
#include <stdexcept>
#include "mighty_sdk.h"

std::ifstream file("2026-rebuilt-welded.json");
std::string json((std::istreambuf_iterator<char>(file)), {});
mighty_protocol::sdk::AprilTagMap map;
std::string error;
if (!mighty_protocol::sdk::parse_wpilib_field_layout_json(json, &map, &error))
  throw std::runtime_error(error);
auto result = client.import_wpilib_field_layout(json, 0.1651);
if (!result.ok) throw std::runtime_error(result.message);
```

To upload an edited map, use `serialize_apriltag_map_yaml` (Python),
`serializeApriltagMapYaml` (JavaScript), or `serialize_apriltag_map_yaml` (C++)
and the existing config-set method with key `apriltags`. These serializers
convert WPILib tag axes into the device's tag convention; do not upload the
WPILib quaternion directly as raw device YAML.

See [SDK API Reference](/docs/sdk/api-reference) for signatures and
[SDK Recipes](/docs/sdk/recipes) for the legacy shortcut configuration.
